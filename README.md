# GeoQuest (map repo)

Self-contained interactive maps for BCS exam preparation, published with
GitHub Pages.

**Two things share the name. Don't mix them up:**

| | What it is | Where it lives |
|---|---|---|
| **GeoQuest** (this repo) | The maps themselves: HTML, map data, fonts, build tools | `github.com/conceptq2026-wq/GeoQuest`, served at `https://conceptq2026-wq.github.io/GeoQuest/` |
| **Geo Quest** (app screen) | The screen in the Preli Quest app that shows a map | The ConceptQ app repo |

The only connection is a URL. A map's public address, e.g.
`https://conceptq2026-wq.github.io/GeoQuest/straits/`, is pasted into the app's CMS
(a VaultVisual record's `hosted_url`) and the app opens it in a WebView.
No code, packages or imports are shared in either direction.

## Maps

Every map lives at `<section>/<map-slug>/index.html`. The sections follow the
BCS Preliminary subject divisions, in this order:

| Section | Folder | BCS subject |
|---|---|---|
| Bangladesh | `bangladesh/` | বাংলাদেশ বিষয়াবলি |
| International | `international/` | আন্তর্জাতিক বিষয়াবলি |
| Geography | `geography/` | ভূগোল, পরিবেশ ও দুর্যোগ ব্যবস্থাপনা |

Which section a map belongs to is decided by the project owner, not by
whoever builds the map.

| Map | Section | Folder |
|---|---|---|
| Straits and canals / গুরুত্বপূর্ণ প্রণালি ও খাল — 13 straits, 7 canals | International | `international/straits/` |

`straits/index.html` is a temporary forwarder from the map's old address to
`international/straits/`. It is not listed on the hub and is deleted once the
app's CMS points at the hub.

## Layout

```
index.html            hub: the three sections and a card per map
international/
  straits/            one folder per map → one URL per map
    index.html, app.js, style.css
    data.js           hand-written content: Bengali names and notes, each
                      passage's frame (first view) and route status, SEAS
    routes.geojson    shipping lanes, built from the pinned OSM snapshot (ODbL)
    canals.geojson    each canal's line, built from the pinned OSM snapshot (ODbL)
    famous-lines.geojson  UNUSED: generated by tools/ from data.js, not drawn
                          on any map; waits here for the boundary-lines map
straits/index.html    temporary forwarder to international/straits/ (see above)
shared/               cached once by the WebView, used by every map
  tiles/world.pmtiles       world basemap (see below)
  fonts/noto-sans-bengali/  label font + OFL licence
  vendor/maplibre-gl-6.9.0/ map library (pinned)
  vendor/pmtiles-4.5.0/     reads .pmtiles with HTTP range requests (pinned)
tools/                build pipeline (Node only, no GDAL/tippecanoe needed)
  sources/osm-tss.geojson     dated OpenStreetMap snapshots (ODbL), committed:
  sources/osm-canals.geojson  lanes and canal lines
```

**Where a file goes.** Used by more than one map → `shared/`. Used by exactly
one map → that map's folder. A map two folders deep reaches shared files with
`../../shared/`. `world.pmtiles` is never duplicated and never grows to serve a
single map: higher-detail tiles for one region are a separate `.pmtiles`
file, in `shared/` only if more than one map uses it.

## Rules every map follows

- **All data served from this repo.** Map data is a `.pmtiles` file read with
  HTTP range requests. No tile servers, no CDNs, never `demotiles.maplibre.org`,
  no API-key services.
- **Exact versions.** Libraries live in folders named with their version, and
  `tools/package.json` pins exact versions. A new release can never change a
  published map without a deliberate edit.
- **Low-end Android first.** The straits map downloads about 400 KB on first
  visit (compressed), of which about 19 KB is map data for the opening view.
  The old version was about 2 MB, including 5.5 MB of GeoJSON the phone had to parse.
- **Language.** Map controls (Layers menu, accessibility labels) are English. Everything the student reads as content is Bengali:
  place names on the map, the passage names in the dropdown, and the whole
  information card, including its field labels (দেশ, সংযোগ, সীমানা).
- **Credits behind ⓘ.** Attribution stays on the page (Natural Earth, MapLibre,
  and OpenStreetMap's ODbL require it) but sits behind an ⓘ button under the
  compass instead of taking a line of the screen.
- **Attribution.** Every map shows its data credits in the always-visible
  line at the bottom of the map.
- **Light palette.** Pale blue sea, warm off-white land, dark labels on white
  halos, white controls. A teaching map on a phone needs a clear land/sea edge
  more than a sophisticated look. Grey text is never lighter than `#5b6878` on
  white.
- **One way back.** Every map has a single "← All maps" link at the top left,
  a relative link to the hub's `index.html` (not `history.back()`: a map can
  be opened directly with no history). On screens narrower than 380 px the
  dropdown wraps to its own row under it; a Bengali name is never truncated.
- **Built to be embedded.** The app opens a map in a full-screen viewer that
  already shows the map's title, so a map page has no visible heading (the
  `<h1>` is screen-reader only). The viewport tag disables page zoom
  (`maximum-scale=1, user-scalable=no`), so a pinch zooms the map, not the
  page. On phones the page is exactly one screen tall and the map fills what
  is left, so a drag always pans the map rather than scrolling the page.

## Verified on a real phone

2026-09-18, the straits map inside the Preli Quest app's Android WebView:
WebGL renders, Bengali labels render including conjuncts, PMTiles range reads
work over GitHub Pages, and the page's own strait panel draws correctly. This
closes the "not yet tested on a real phone / in the app WebView" items. Still
untested: iOS, and a genuinely low-end Android device.

## Serving from GitHub Pages

Pages serves `main` from the repo root. Two behaviours to know about:

**Range requests and compression.** Pages supports HTTP range requests
(`206 Partial Content`), which PMTiles depends on. Checked live on
2026-09-18: a browser read the opening Hormuz view in 5 range requests,
18.6 KB in total, and the bytes matched the file in the repo.

> **Any non-browser tool that reads these `.pmtiles` files over HTTP must send
> `Accept-Encoding: identity`.** If a request says it accepts gzip, Pages
> returns a *slice of a gzipped copy of the file*. It is still `206`, with a
> plausible `Content-Range` (`bytes 0-16383/1152391` instead of
> `/1294397`) and `Content-Encoding: gzip`, so it looks like valid data but is
> not.
>
> Browsers and WebViews are safe. The Fetch standard requires them to send
> `Accept-Encoding: identity` whenever a `Range` header is present, so the
> app's WebView gets the real bytes. `curl`, scripts and server-side readers
> don't do that automatically. Set the header yourself, e.g.
> `curl -H "Range: bytes=0-16383" -H "Accept-Encoding: identity" …`.

**10-minute cache.** Pages sends `Cache-Control: max-age=600`. After a push, a
phone (or the app's WebView) can keep showing the old version for up to
10 minutes. That is caching, not a broken deploy. Wait it out, or check a
fresh copy with `curl -I` before assuming something is wrong.

## The world basemap: `shared/tiles/world.pmtiles`

| Zooms | Coverage | Source |
|---|---|---|
| 0–6 | whole world | Natural Earth 1:50m |
| 7–10 | only inside the boxes in `tools/world.config.mjs` | Natural Earth 1:10m |

1:50m can't show narrow waterways: at the Bosporus zoom it draws a 0.7 km strait
as a straight wedge. The detail boxes fix that without shipping 1:10m for the
whole world. A page reads the file as two sources: `world` (0–6, overzooms
beyond) and `detail` (7–10), where `detail` paints an ocean-coloured mask
over the 1:50m shapes. A small coastline step is visible at a box edge, so
boxes are drawn well outside the view each map opens at.

Layers: `land`, `lakes`, `borders`, `disputed`, `country_labels` (Bengali
`name_bn`), and `detail_extent` for zooms 7–10. Natural Earth's land polygons
fill lakes in as land, so `lakes` (1:50m, 1:10m in the detail boxes) is drawn
as water on top — the Great Lakes and Gatun Lake are what the Soo, Welland and
Panama canals run through.

## Straits map: what is drawn and why

- **Passages** (`PASSAGES` in `international/straits/data.js`, approved 2026-09-18): 13 straits
  — Hormuz, Malacca, Bab el-Mandeb, Gibraltar, Bosporus, Dardanelles, Bering,
  Palk, Sunda, Dover, Magellan, Formosa, Cook — and 7 canals — Suez, Panama,
  Kiel, Corinth, Soo, Welland, Grand Canal. The dropdown groups them under
  প্রণালি / খাল. Spelling is প্রণালি everywhere, matching Natural Earth's own
  labels. Formosa follows Bangladesh's point of view: দেশ reads "চীন (মূল ভূখণ্ড
  — তাইওয়ান দ্বীপ)".
- **Nothing unverified reaches the card.** A card row whose value is `null` is
  hidden, never filled with a guess. Canal opening years and lengths (চালু,
  দৈর্ঘ্য) are `null` on purpose until checked against the textbook BCS uses —
  sources disagree (Suez 164 or 193 km, Panama 77 or 82 km). The new straits'
  সীমানা notes are `null` until written.

- **First view of a passage** is a hand-set `frame` in `international/straits/data.js`:
  both neighbouring countries and a clear piece of each connected sea, so a
  student first sees where the passage is and what it joins; pinching in shows
  how narrow it is. Frames are hand-set on purpose — computing them from label
  positions put Gibraltar at a third of the world. `verify` checks each frame
  contains the passage and both of its sea labels.
- **World view clustering.** Passage points closer than 25 px merge into one
  navy circle with a Bengali count (২, ৩…); tapping it zooms in until they
  separate (clustering stops above zoom 6). 25 px, not 40: at 40 every passage
  merged on a portrait phone and the opening view showed only numbers.
- **Shipping lanes start at zoom 4.** Below that they carry no information. Offsetting points (wrong places)
  and letting labels hide each other (a hidden point can't be tapped) were
  rejected.
- **Connected seas** (`SEAS` in `data.js`) are labelled in blue. The chosen
  passage's two seas are always shown; the passage's own name moves to
  whichever side of its point is free.
- **Shipping lanes are only ever drawn from mapped data.** They are the
  International Maritime Organization traffic-separation schemes as mapped in
  OpenStreetMap (`seamark:type=separation_*`): separation zones, boundaries and
  the one-way lanes with arrows. Nothing is guessed or hand-joined — a guessed
  line shown as the real channel teaches something false. Each passage's
  `routeStatus` says what the card tells the student:

  | routeStatus | Card (নৌপথ) | Passages today |
  |---|---|---|
  | `mapped` | নির্ধারিত নৌপথ (IMO ট্রাফিক বিভাজন ব্যবস্থা) মানচিত্রে দেখানো হয়েছে | Malacca, Bab el-Mandeb, Gibraltar, Bosporus, Dover |
  | `partial` | আংশিক — নির্ধারিত নৌপথের কেবল কিছু অংশ মানচিত্রে আছে | Hormuz, Dardanelles |
  | `none` | এখানে কোনো নির্ধারিত নৌপথের মানচিত্রায়িত তথ্য নেই | Bering, Palk, Sunda, Magellan, Formosa, Cook |
  | `canal` | খালটিই নৌপথ — খালের পথ মানচিত্রে দেখানো হয়েছে | all 7 canals |

  **The map and the card must agree.** Inside the frame of a `none` passage,
  no lane is drawn at all — not even a real scheme nearby. Formosa and Cook
  have port-approach schemes in OSM (Xiamen/Penghu, Wellington harbour), not a
  lane through the strait; drawn beside "তথ্য নেই" they would tell the student
  the opposite, and a drawn line wins. The build drops them and `verify`
  checks no `none` frame contains a lane.
- **Canals** are drawn from each canal's own navigation line in OpenStreetMap,
  in blue with a white casing, always visible. One explicit selector per canal
  (`tools/extract-osm-canals.mjs`) picks the named main line, not every side
  canal nearby. The Soo is drawn from the Soo Locks (Poe and MacArthur), which
  OSM maps as St. Marys River segments tagged `lock=yes`. The Grand Canal has
  gaps where OSM's segments carry no name — left as is: what is drawn is real,
  and a hand-drawn join would be the same mistake as hand-tracing Hormuz.

  Statuses were set by looking at each scheme through the narrows, not by
  counting ways. Hormuz is deliberately `partial` and NOT hand-traced: it is the
  passage students ask about most, which is exactly where a confident-looking
  approximation would do the most damage.
- **The OSM data is committed snapshots**, `tools/sources/osm-tss.geojson` and
  `osm-canals.geojson` (fetched 2026-09-18 by `npm run extract-osm`, pinned by
  SHA-256 in `sources.json`). The build never calls the live API, so lanes and
  canals only change when someone re-extracts and reviews the diff.

### Bangladesh point of view

Natural Earth v5.1.2 publishes point-of-view data for Bangladesh:
`ne_10m_admin_0_countries_bdg.geojson` and an `FCLASS_BD` field on every
boundary line. The basemap uses it:

- boundary lines with `FCLASS_BD = 'Unrecognized'` are dropped, and other
  `FCLASS_BD` values override the default class (`tools/lib/geo.mjs`);
- country labels come from the Bangladesh file. For example, it has no separate
  Israel (the area is Palestine) and no separate Taiwan (it is part of China).

One deliberate exception, for when the famous-lines data gets its own map:
the famous-lines build traces the **Green Line** even though Bangladesh's view
drops that line from the basemap borders, because the line is the subject of
the lesson. Those segments are tagged `bdPov: 'unrecognized'` in
`famous-lines.geojson`, and the build prints them. (The straits map no longer
draws famous lines at all.)

## Bengali labels

MapLibre's old approach (prebuilt glyph files) can't shape Bengali. Conjuncts
and vowel signs come out broken. Instead the style uses MapLibre's
`font-faces` property with a bundled Noto Sans Bengali, so the browser does the
shaping. Tested: প্র, the pre-base ি and the split vowel কৌ render the same on
the map as in normal page text. Characters the font lacks (Latin letters, `–`,
`†`, e.g. in "নিয়ন্ত্রণ রেখা (LoC)") fall back to a system font.

**This is why MapLibre stays pinned at 6.9.0.** As of this writing the style-spec
docs still list `font-faces` as *not supported* on GL JS. It works in 6.9.0
(it shipped there without the docs catching up). Before moving to any other
version, re-test Bengali labels on a real map, not just the release notes.

## Building

Needs Node 20+. From `tools/`:

```bash
npm ci
npm run build
```

`build` runs these steps in order:

1. `fetch`: downloads every input in `tools/sources.json` into `tools/.cache/`
   (gitignored). Natural Earth comes from one fixed commit (tag v5.1.2) and each
   file must match the git blob hash in that commit. The font zip must match
   GitHub's published SHA-256. Any mismatch stops the build.
2. `vendor`: copies MapLibre and pmtiles from `node_modules` into `shared/vendor/`.
3. `font`: builds the Noto Sans Bengali WOFF2 and copies its OFL licence.
4. `world`: builds `shared/tiles/world.pmtiles`.
5. `straits`: builds `international/straits/famous-lines.geojson` from `international/straits/data.js`.
6. `routes`: builds `international/straits/routes.geojson` and `international/straits/canals.geojson` from
   the pinned OSM snapshots (refuses a snapshot whose checksum doesn't match
   `sources.json`).
7. `verify`: reads the archive back with the official pmtiles reader, checks
   tiles and ring winding, the vendored files against the npm packages, every
   passage's frame, route status and the OSM snapshot's checksum.

`npm run extract-osm` is NOT part of `build`: it refreshes the OSM snapshot from
the live Overpass API and is only run on purpose.

The build is deterministic: re-running it produces byte-identical files.

The straits map's folder is set once, as `STRAITS_DIR` at the top of each
script that reads or writes it (`build-straits-overlay`, `build-straits-routes`,
`extract-osm-tss`, `verify`). If the map moves, that is one edit per script.

Notes for the next map:

- **Ring winding** (`tools/lib/geo.mjs`): Natural Earth polygons don't all
  run in the same direction, and vector tiles use direction to tell land from
  holes. Without `rewind()`, land renders as sea in patches. This was first seen at
  Hormuz. Every polygon source must go through `prepare()`.
- `tools/lib/pmtiles-writer.mjs` writes PMTiles v3 with a single root
  directory (the npm `pmtiles` package only reads). It throws if the root
  directory outgrows 16 KiB. Today it is 9 KB.
- Famous lines are matched by the two countries either side (`match` in
  `international/straits/data.js`), not by "everything inside a box".
